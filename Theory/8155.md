## 1. Introduction to Interfacing (Slides 2–3)

**Typical interfaces in a µP/µC system (Slide 2):**
- Switches, LEDs
- LCD display panels
- Keyboards / keypads (input interfaces)
- Output interfaces, printers
- Input signals from sensors
- ADCs and DACs

**Two ways of interfacing (Slide 3):**

| Directly through µP bus | Through programmable ICs |
|---|---|
| Uses address bus, data bus, control signals | Uses peripheral chips like 8155, 8279 |
| Hard-wired | Very flexible: many peripherals/components can be connected |
| Limited control or changes | Controlled by **software** (program code) |

## 2. 8155 Multipurpose Programmable Device (Slides 4–7)

### Features (Slide 5 – block diagram)
- **256 × 8 static RAM**
- **Port A** (8-bit, PA0–PA7), **Port B** (8-bit, PB0–PB7), **Port C** (6-bit, PC0–PC5)
- **Timer** (14-bit programmable counter/timer **(extra)**) with TIMER CLK (in) and TIMER OUT (out, active low)
- Multiplexed address/data lines **AD0–AD7**, so it connects directly to the 8085
- Control signals: **IO/M̄, CE̅, ALE, RD̅, WR̅, RESET**
- Supply: Vcc = +5 V, Vss = 0 V; 40-pin IC (Vcc pin 40, Vss pin 20)

### Pin diagram (Slide 4)
- Left side: PC3, PC4, TIMER IN, RESET, PC5, TIMER OUT, IO/M̄, CE̅ (CE in 8156), RD̅, WR̅, ALE, AD0–AD7, Vss
- Right side: Vcc, PC2, PC1, PC0, PB7–PB0, PA7–PA0
- Note: 8156 is the same chip with CE (active high) instead of CE̅.

### Internal structure (Slide 6)
- **Internal latch** latches A0–A2 (and A7) from the multiplexed AD bus using ALE.
- **Internal decoder** (enabled by CE̅) uses A2 A1 A0 to select one of 6 registers (outputs 0–5).
- Registers selected: Control register, Port A, Port B, Port C, Timer LSB, Timer MSB.
- Data goes to/from the ports via the internal **data bus** connected to AD0–AD7.

### I/O address map (Slide 7)

| AD2 | AD1 | AD0 | Address | Selected register |
|:-:|:-:|:-:|:-:|---|
| 0 | 0 | 0 | **20H** | Control / Status register |
| 0 | 0 | 1 | **21H** | Port A |
| 0 | 1 | 0 | **22H** | Port B |
| 0 | 1 | 1 | **23H** | Port C |
| 1 | 0 | 0 | **24H** | Timer (LSB) |
| 1 | 0 | 1 | **25H** | Timer (MSB) |

*(Base address 20H comes from the chip-select decoding of the higher address lines in this example.)*

### Control word format **(extra)**
| Bits | Function |
|---|---|
| D0 | Port A: 1 = output, 0 = input |
| D1 | Port B: 1 = output, 0 = input |
| D3 D2 | Port C mode (00 = all input, 11 = all output, 01/10 = handshake modes) |
| D4, D5 | Interrupt enable for Port A, Port B |
| D7 D6 | Timer command (00 = no effect, 01 = stop, 10 = stop after TC, 11 = start) |

## 3. Interfacing 8155 with 8085 – Example (Slides 8–9)

### Circuit explanation (Slide 8)
**Goal:** Display data on **four hex digits / two 7-segment pairs** using ports A and B.

- **8155 ↔ 8085 connections:** AD0–AD7 → 8155 AD0–AD7; IO/M̄, ALE, RD̅, WR̅ connected directly; RESET OUT of 8085 → RESET of 8155; CE̅ (pin 8) driven by the address-decoding logic of the 8085.
- **Port A (PA7–PA0)** is split into two nibbles:
  - PA7–PA4 → first **HP 5082/7340** display (hex/BCD display with built-in latch/decoder)
  - PA3–PA0 → second HP 5082/7340 display
  - So Port A directly shows one byte as two hex digits.
- **Port B (PB7–PB0)** is also split into two nibbles:
  - PB7–PB4 → **Fairchild 9370** (hex decoder/driver) → common-anode 7-segment LED
  - PB3–PB0 → second **Fairchild 9370** → second common-anode 7-segment LED
  - Each segment line passes through a **330 Ω** current-limiting resistor.
  - Common anodes go to +5 V; the decoder's LE̅ is tied for continuous (transparent) operation.
- **Key idea:** Each port pin group sends a 4-bit code to a decoder; the decoder turns it into segment signals.

#### System working flow (Slides 8–9 together)
1. **Reset:** the 8085 RESET OUT signal resets the 8155, and all ports start as **inputs**.
2. **Initialise:** the program does `MVI A,03H` and `OUT 20H`.
   - During `OUT`, the 8085 puts the port address (20H) on the address/data bus, and ALE latches it.
   - IO/M̄ = 1 (I/O cycle), the CE̅ decoder recognises the address and enables the 8155, and WR̅ goes low.
   - The 8155's internal latch takes A2 A1 A0 = 000, so the **control register** is selected and 03H is written into it. Ports A and B now become **outputs**.
3. **Send first byte:** `MVI A,BYTE1` and `OUT 21H` select **Port A** (A2 A1 A0 = 001). BYTE1 is latched on PA7–PA0 and stays there.
4. **Port A to display:** PA7–PA4 (high nibble) drives the first HP 5082/7340 and PA3–PA0 (low nibble) drives the second, so each shows one **hex digit**.
5. **Send second byte:** `MVI A,BYTE2` and `OUT 22H` select **Port B** and latch BYTE2 on PB7–PB0.
6. **Port B to display:** each nibble goes to a Fairchild 9370 decoder/driver, which converts the 4-bit code into the 7 segment signals. The signals go through the 330 Ω resistors to the common-anode LED, which lights the matching digit.
7. **HLT:** the CPU stops, but the port latches **hold** their data, so the display stays lit.

**Block flow:** `8085 → (AD bus + IO/M̄ + WR̅ + CE̅) → 8155 control register → Port A / Port B latch → decoder/driver → 7-segment display`

### Control word and program (Slide 9)
- Addresses: Control register = **20H**, Port A = **21H**, Port B = **22H**
- Control word to make **ports A and B outputs** = `0000 0011` = **03H**
  - D7–D6 = 00 → no effect on timer
  - D5–D4 = 00 → not applicable
  - D3–D2 = 00 → Port C not used
  - D1 = 1 → Port B output; D0 = 1 → Port A output

```asm
MVI A,03H        ; (slide shows "MCI", a typo for MVI)
OUT 20H          ; initialize ports A and B as output ports
MVI A,BYTE1
OUT 21H          ; display BYTE1 at port A
MVI A,BYTE2
OUT 22H          ; display BYTE2 at port B
HLT
```
**Steps to remember:** (1) write control word → (2) load data into accumulator → (3) OUT to port address.

**Program execution flow:** `MVI A,03H` loads the control word into A → `OUT 20H` copies A into the 8155 control register (ports configured) → `MVI A,BYTE1` → `OUT 21H` (Port A latch updated, display 1 changes) → `MVI A,BYTE2` → `OUT 22H` (Port B latch updated, display 2 changes) → `HLT`.

## 4. Hardware Interfacing Examples (Slides 10–12)

### Slide 10 – Building blocks
| 74LS373 – 8-channel **latch** | 74LS245 – 8-channel **bidirectional buffer** |
|---|---|
| Pins: D0–D7 (inputs), Q0–Q7 (outputs), CLK (latch enable, pin 11), OE̅ (pin 1) | Pins: A0–A7, B0–B7, DIR (pin 1), CS̅ (pin 19) |
| Holds data on its outputs → used for **output ports** | Passes data either way between two buses → used for **input ports** / bus buffering |
| OE̅ low enables outputs | DIR chooses direction (A→B or B→A); CS̅ low enables the chip, high puts it in high-Z |

### Slide 11 – Switch input port (8086 + 74LS245)
- 8 switches (SW1–SW8) connected to the **B-side** lines (shown as O0–O7), each with a **10 kΩ pull-down** resistor to ground and the other end to Vcc.
  - Switch open → logic 0; switch closed → logic 1.
- **DIR is grounded**, so data flows from the switches toward the 8086 data bus (D0–D7). Only reading is needed.
- **Chip-select logic:** address lines A15–A8 go into one gate and A7–A0 into another; their outputs and **IORD̅** go to a third gate whose output drives **CS̅** of the 74LS245. The buffer is enabled only when the correct 16-bit I/O address is on the bus **and** IORD̅ is active.
- Software: `IN AL, port` reads the switch positions into AL.
- **Concept:** Input devices need a **tri-state buffer** so they do not load the bus except when read.

#### System working flow
1. The user sets the switches. A closed switch puts Vcc (logic 1) on its line, and an open switch is pulled to ground by its 10 kΩ resistor (logic 0). The 74LS245 is **disabled** (high-Z) at this stage, so the data bus is not loaded.
2. The 8086 executes `IN AL, port`. It places the 16-bit I/O address on A15–A0 and makes **IORD̅ = 0**.
3. The address gates compare A15–A0 with the port address. If they match **and** IORD̅ = 0, the final gate makes **CS̅ = 0**.
4. The 74LS245 is enabled. With **DIR = 0** the data direction is *switches → data bus*, so the switch levels appear on D0–D7.
5. The 8086 takes the data from D7–D0 into **AL** at the end of the read cycle.
6. IORD̅ returns to 1, so CS̅ = 1 and the buffer goes back to high-Z. If any other address is used, the buffer stays disabled.

**Block flow:** `Switches → 74LS245 (enabled by address decode + IORD̅) → D0–D7 → 8086 AL register`

### Slide 12 – Fig. 5.13: Switches and displays (Problem 5.7)
Combines an **input port** and an **output port**.
- **Input (top):** Same 74LS245 switch circuit; CS̅ is generated by a NAND of the address bits (PA3–PA0) and **IORD̅**.
- **Output (bottom):** **74LS373** latch.
  - D0–D7 from the data bus; **CLK** is driven by **IOWR̅ through an inverter** (the latch captures data when the write pulse ends).
  - Its select (OE̅ / CS̅) is derived from the address bits PA3–PA0.
  - Outputs Q3–Q0 → inputs A, B, C, D of a **BCD to 7-segment decoder** → segments a–g through **270 Ω** resistors → 7-segment display.
- **Flow summary:** read switches → process → write BCD value to the latch → digit is displayed.

#### System working flow
**Input path (read switches):**
1. `IN AL, port` puts the address on the bus and makes IORD̅ = 0.
2. The NAND of the address bits (PA3–PA0) and IORD̅ makes the 74LS245's **CS̅ = 0**.
3. With DIR = 0, the switch states go onto D0–D7, and the 8086 loads them into AL.

**Output path (display a digit):**
1. The program places the value (BCD, 0–9) in AL, e.g. after `AND AL,0FH` to keep only the low nibble.
2. `OUT port, AL` puts the output port address on the bus. The address decoder (PA3–PA0 gate) enables the 74LS373 through its **CS̅/OE̅** pin. The data appears on D0–D7 and **IOWR̅ goes low**.
3. The inverter turns the low IOWR̅ into a **high CLK (LE)** pulse, so the latch is transparent and follows the data bus.
4. When the write ends, IOWR̅ returns high and CLK falls. The latch **holds** the data on Q3–Q0.
5. Q3–Q0 go to the A, B, C, D inputs of the **BCD to 7-segment decoder**. It produces the signals a–g, which pass through the 270 Ω resistors and light the digit.
6. The digit stays displayed until the next `OUT` changes the latch.

**Overall flow:** `Switches → 74LS245 → data bus → 8086 (AL) → data bus → 74LS373 → BCD to 7-seg decoder → display`

## 5. 8279 – Programmable Keyboard and Display Interface (Slides 13–15)

### Pin configuration (Slide 13) – 40-pin IC
| Pin(s) | Type | Function |
|---|:-:|---|
| DB0–DB7 | I/O | Bidirectional data bus |
| CLK | I | Clock input |
| RESET | I | Reset input |
| CS̅ | I | Chip select |
| RD̅, WR̅ | I | Read / write |
| A0 | I | Buffer address (selects data or command/status) |
| IRQ | O | Interrupt request output |
| SL0–SL3 | O | Scan lines |
| RL0–RL7 | I | Return lines (keyboard) |
| SHIFT | I | Shift input |
| CNTL/STB | I | Control / strobe input |
| OUT A0–A3, OUT B0–B3 | O | Display outputs (A and B nibbles) |
| BD̅ | O | Blank display output |

Logic symbol groups: **CPU interface** (data bus, RD̅, WR̅, CS̅, A0, Reset, CLK, IRQ), **Key data** (RL0–7, SHIFT, CNTL/STB), **Scan** (SL0–3), **Display data** (OUT A0–3, OUT B0–3, BD̅).

### Hardware architecture (Slide 14)
Blocks and their roles:
- **I/O control + Data buffers:** interface with the CPU (RD̅, WR̅, CS̅, A0, DB0–DB7).
- **Control and timing registers + Timing and control:** store the mode/commands and generate internal timing.
- **Scan counter:** generates scan lines SL0–SL3 (encoded or decoded).
- **Return buffer / Keyboard debounce and control:** reads RL0–RL7, SHIFT, CNTL/STB; removes key bounce.
- **8 × 8 FIFO/Sensor RAM:** stores key codes (FIFO) or sensor states; **FIFO status** logic generates **IRQ**.
- **16 × 8 Display RAM** + **Display address registers** + **Display registers:** hold the characters to display and send them out via OUT A0–A3, OUT B0–B3.
- **BD̅** blanks the display during digit switching.

**Features (extra):** scans keyboard up to 8 × 8 (64 keys) plus shift & control; 2-key lockout / N-key rollover; auto debounce; drives up to 16 seven-segment digits (multiplexed); display RAM 16 × 8; left or right entry.

**Command words (extra, A0 = 1 for command):** 000 Mode set · 001 Program clock · 010 Read FIFO · 011 Read display RAM · 100 Write display RAM · 101 Display write inhibit/blanking · 110 Clear · 111 End interrupt/error mode set.

### Example circuit for interfacing (Slide 15)
Primer Trainer display/keypad board (EMAC Inc.).

- **CPU side:** D0–D7 → DB0–DB7; RD*, WR*; **8279CS*** (chip select from address decoder); SYSCLK → CLK; RESET; A0 → A0; **IRQ → KEYINT** (key interrupt to the CPU); 0.1 µF capacitor (C7) on the supply for decoupling.
- **Keypad scanning:**
  - Scan lines **SL0–SL2** go to a **74HC138 (3-to-8 decoder)** → produces **SC0*–SC6*** (SC7* unused).
  - **KP1: hex 4 × 4 keypad (0–F)** uses scan lines SC0–SC3 and return lines RL0–RL3 (C0–C3). Optional extra rows **KP2** (SC5*) and **KP3** (SC6*) are 1 × 4 hex rows. SC4*/SC7* are not used by the keypad matrix.
  - RL4–RL7, SHIFT, CNTL/STB left **NC** (not connected).
- **Display driving:**
  - OUT A0–A3 and OUT B0–B3 → **UDN2981A** (8-channel source driver, "anode bus") → **120 Ω** resistors → segments **a–g, DP** of the displays.
  - Three dual-digit displays **DS1, DS2, DS3 (LTD6940HR)** = 6 digits, common cathode.
  - Digit selection ("scan bus"): scan lines select a digit via transistors **Q1–Q6 (2N4403)** on the cathodes, so only one digit is on at a time (multiplexing).
  - Column scanning goes **from right to left**.
- **Operation:** the 8279 scans the keypad and the display simultaneously with the same scan lines; the CPU only reads key codes from the FIFO and writes characters to the display RAM.

#### System working flow
**Step 1 – Initialisation (CPU to 8279, A0 = 1 for commands):**
1. After RESET, the CPU writes the **mode-set command** (keyboard type and display type, e.g. 8-character left entry).
2. It writes the **clock-program command** to divide SYSCLK to the internal scan frequency (about 100 kHz).
3. It writes the **clear command** to blank the display RAM and the FIFO.

**Step 2 – Showing characters (output flow):**
1. The CPU writes the **write-display command** (A0 = 1), then the data bytes (A0 = 0) into the **16 × 8 display RAM**.
2. The 8279 scans the display RAM on its own. For each digit position it puts the segment code on OUT A0–A3 and OUT B0–B3 and the digit number on SL0–SL2.
3. The **UDN2981A** driver amplifies the segment code (through the 120 Ω resistors), and the **74HC138 output (SC*) turns on the transistor** (Q1–Q6) of the selected digit.
4. This repeats quickly for all digits (**multiplexing**), so the eye sees every digit lit steadily. The CPU is free after the write.

**Step 3 – Key press (input flow):**
1. The scan lines keep driving the rows SC0*–SC3* (and SC5*, SC6*) in turn. These are the **same scan lines** used for the display.
2. When a key is pressed, its row signal reaches a return line (RL0–RL3). The 8279 notes which scan line and which return line are active.
3. The **debounce logic** confirms the key (about 10 ms) and ignores contact bounce.
4. The 8279 builds the key code (scan position + return line + SHIFT/CNTL bits) and stores it in the **8 × 8 FIFO**.
5. As soon as the FIFO is not empty, **IRQ goes high**, which reaches the CPU as **KEYINT**.
6. The CPU runs its ISR and does a read with **A0 = 0**, RD̅ low and 8279CS* low. The key code comes over D0–D7 and the FIFO pointer moves on.
7. When the FIFO is empty, IRQ goes low. The CPU decodes the key code (e.g. through a look-up table) and acts on it, perhaps by writing a new digit to the display RAM (back to Step 2).

**Block flow:** `Keypad ⇄ scan lines (74HC138) ⇄ 8279 ⇄ FIFO / display RAM ⇄ CPU; 8279 → UDN2981A + transistors → 7-segment displays`

## 8. Last-Minute Revision Points
- 8155 = **RAM (256 B) + 3 ports (8, 8, 6 bit) + timer**; addresses **20H–25H** in the example.
- Control word **03H** → A and B outputs. Always write the control word to **20H first**.
- **IO/M̄ = 1** selects I/O in the 8155; AD0–AD2 select the register.
- **74LS373 = latch (outputs)**, **74LS245 = bidirectional buffer (inputs)**; DIR sets direction, CS̅ enables.
- Output ports → latch with write strobe (IOWR̅); input ports → buffer with read strobe (IORD̅).
- 8279 = **keyboard (RL, SL, FIFO)** + **display (OUT A/B, 16×8 RAM)**; **A0** differentiates data vs command; **IRQ** informs the CPU of a key press.
- 74HC138 decodes scan lines into individual row strobes; UDN2981A drives the segments; transistors select digits.
- Slide typo: `MCI A,03H` should be `MVI A,03H`.
