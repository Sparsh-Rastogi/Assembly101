## 1. Quick Overview (Slides 2–3)

- **8255 / 8255A** = Programmable Peripheral Interface (PPI), a **40-pin DIP** general-purpose parallel I/O chip.
- Has **24 I/O lines** arranged as three 8-bit ports: **Port A, Port B, Port C**.
- Port C can be split into **Upper (PC7–PC4)** and **Lower (PC3–PC0)** nibbles.
- Ports are grouped for control:
  - **Group A** = Port A + Port C upper
  - **Group B** = Port B + Port C lower
- Operating modes: **BSR mode** and **I/O mode** (Mode 0, 1, 2).
- Supply: **Vcc = +5 V**, GND.

| Pins | Signal | Function |
|---|---|---|
| 1–4, 37–40 | PA0–PA7 | Port A lines |
| 18–25 | PB0–PB7 | Port B lines |
| 10–17 | PC0–PC7 | Port C lines |
| 27–34 | D0–D7 | Bidirectional data bus |
| 5 | RD̅ | Read, active low |
| 36 | WR̅ | Write, active low |
| 6 | CS̅ | Chip select, active low |

| 26 | Vcc | +5 V |
| 7 | GND | Ground |

**Remember:** A1 A0 select one of 4 internal registers (Port A, B, C, Control Word Register CWR).

## 3. Internal Architecture (Slide 3, Fig. 5.17(a))

Main blocks:

1. **Data Bus Control Buffer** – 8-bit tri-state bidirectional buffer; interfaces D0–D7 with the system data bus. Carries data, control words and status.
2. **Read/Write Control Logic** – takes RD̅, WR̅, A0, A1, RESET, CS̅ and issues commands to Group A and Group B control blocks. CS̅ is the master enable.
3. **Group A Control** – controls Port A and Port C upper (PC7–PC4).
4. **Group B Control** – controls Port B and Port C lower (PC3–PC0).
5. **Port A** (PA7–PA0), **Port B** (PB7–PB0), **Port C upper/lower** – the actual I/O ports.
6. **Internal data bus** connects the buffer to both group controls and ports.

## 4. Operation Tables (Slide 4, Table 5.9)

### (a) Read (input) cycle – RD̅=0, WR̅=1, CS̅=0

| A1 | A0 | Action |
|---|---|---|
| 0 | 0 | Port A → data bus |
| 0 | 1 | Port B → data bus |
| 1 | 0 | Port C → data bus |
| 1 | 1 | CWR → data bus |

### (b) Write (output) cycle – RD̅=1, WR̅=0, CS̅=0

| A1 | A0 | Action |
|---|---|---|
| 0 | 0 | Data bus → Port A |
| 0 | 1 | Data bus → Port B |
| 1 | 0 | Data bus → Port C |
| 1 | 1 | Data bus → CWR |

### (c) Disable / tristate

- CS̅ = 1 (RD̅, WR̅, A1, A0 = X) → data bus tristated.
- RD̅ = 1, WR̅ = 1, CS̅ = 0 → data bus tristated.

> **Note:** Slide 4 lists "CWR to data bus" for a read at A1A0 = 11. On the actual 8255A hardware the control word is write-only; reading is not a normal operation. Follow the slide for exams unless told otherwise.

## 5. Control Word Register (CWR) – I/O Mode (Slide 5)

Format: **B7 B6 B5 B4 B3 B2 B1 B0**

| Bit | Meaning |
|---|---|
| **B7** | **1 = I/O mode**, 0 = BSR mode |
| **B6 B5** | Mode of **Group A** |
| **B4** | Port A: 0 = output, **1 = input** |
| **B3** | Port C upper: 0 = output, **1 = input** |
| **B2** | Mode of Group B (Port B): 0 = Mode 0, 1 = Mode 1 |
| **B1** | Port B: 0 = output, **1 = input** |
| **B0** | Port C lower: 0 = output, **1 = input** |

**Group A mode select**

| B6 | B5 | Mode |
|---|---|---|
| 0 | 0 | Mode 0 |
| 0 | 1 | Mode 1 |
| 1 | 0 | Mode 2 |
| 1 | 1 | X (not used) |

Key rules from slide:
- Port B mode is 0 or 1 depending on **B2**.
- A port is an **output port if its bit is 0**, otherwise it is an **input port**.
- Group B has **no Mode 2**.

**Mode summary (standard knowledge):**
- **Mode 0** – simple I/O, no handshaking; outputs latched, inputs not latched.
- **Mode 1** – strobed I/O with handshake signals (uses Port C lines).
- **Mode 2** – bidirectional bus (Port A only), uses 5 Port C lines for handshake.

---

## 6. BSR Mode (Slide 6, Fig. 5.18(a), Table 5.10)

BSR = **Bit Set/Reset**. Used to set or reset **individual bits of Port C only**.

| Bit | Meaning |
|---|---|
| **B7** | **0 = BSR mode** (note: slide figure shows the mode bit as the flag; for BSR it must be 0) |
| B6 B5 B4 | Don't care (X) |
| **B3 B2 B1** | Bit select: 000 → PC0 … 111 → PC7 |
| **B0** | **1 = Set, 0 = Reset** |

| B3 B2 B1 | Port C bit |
|---|---|
| 000 | PC0 |
| 001 | PC1 |
| 010 | PC2 |
| 011 | PC3 |
| 100 | PC4 |
| 101 | PC5 |
| 110 | PC6 |
| 111 | PC7 |

**Example:** Set PC3 → B7=0, XXX=000, B3B2B1=011, B0=1 → `0000 0111` = **07H**. Reset PC3 → **06H**.

> Slide 6's figure labels B7 as "1" with the caption "0-for BSR mode". The correct BSR control word has **B7 = 0**.

## 7. Problem 1 – Switches and LEDs (Slides 7–11)

**Problem (Slide 7):** Interface 8255 with 8086 as I/O port. Port A = output, Port B = input, Port C = output. Port A address = **0740H**. Read switches SW0–SW7 on Port B, display the pattern on 8 LEDs at Port A, and show the **number of ON switches** on Port C lower.

### Control word (Slide 7)

| B7 | B6 B5 | B4 | B3 | B2 | B1 | B0 |
|---|---|---|---|---|---|---|
| 1 | 00 | 0 | 0 | 0 | 1 | 0 |
| I/O mode | Group A Mode 0 | A out | C upper out | B Mode 0 | B in | C lower out |

**Control word = 1000 0010 = 82H**

### Port addresses (Slide 8)

A15–A12 = 0000, A11–A8 = 0111, A7–A4 = 0100, A3 A2 = 0 0, A1 A0 as below. Even addresses are used because A1 and A2 of 8086 connect to A0 and A1 of 8255 (A0 of 8086 is used for chip select, so the 8255 sits on the **lower (even) data bus D0–D7**).

| Port | Address |
|---|---|
| Port A | **0740H** |
| Port B | **0742H** |
| Port C | **0744H** |
| CWR | **0746H** |

### Circuit (Slide 9)

- 8255 **A0, A1 ← 8086 A1, A2** (so ports are 2 apart).
- **CS̅** is generated by a NAND/AND-gate network that decodes **A15–A8** (one gate), **A7–A3** (another gate) and **A0** (third gate). CS̅ goes low only for the 0740H–0746H range with A0 = 0.
- **D7–D0** connect to 8086 lower data bus.
- **RD̅ ← IORD̅, WR̅ ← IOWR̅, Reset ← system Reset.**
- **Port A (PA7–PA0)** → 8 LEDs, each through a **220 Ω** resistor to ground.
- **Port B (PB7–PB0)** ← 8 switches. Each switch connects the line to +5 V or GND; a **10 kΩ** resistor is used on the supply side.
- Port C lines (PC3–PC0) available for displaying the count.

### Program (Slide 10)

```asm
MOV DX, 0746H      ; address of CWR
MOV AL, 82H        ; control word
OUT DX, AL         ; initialise 8255
SUB DX, 04         ; DX = 0742H (Port B)
IN  AL, DX         ; read switches
SUB DX, 02         ; DX = 0740H (Port A)
OUT DX, AL         ; display on LEDs
MOV BL, 00H        ; ON-switch counter
MOV CH, 08H        ; 8 switches
YY: ROL AL         ; MSB -> carry
JNC XX             ; carry 0 -> switch off
INC BL             ; carry 1 -> count it
XX: DEC CH
JNZ YY             ; repeat for 8 bits
MOV AL, BL         ; count -> AL
ADD DX, 04         ; DX = 0744H (Port C)
OUT DX, AL         ; show count on Port C lower
HLT
```

**Logic:** rotate AL left 8 times through carry; each time carry = 1, increment BL. BL ends up holding the number of ON switches.

### How the system works – step-by-step flow (Problem 1)

```
Start
  |
  v
8086 puts 0746H on address bus -> decoder makes CS=0, A1A0=11 (CWR selected)
  |
  v
OUT DX,AL with AL=82H -> IOWR=0 -> control word latched in CWR
  => Port A = output, Port B = input, Port C = output (all Mode 0)
  |
  v
IN AL,DX (DX=0742H) -> IORD=0, A1A0=01 -> Port B data (switch pattern) -> D7-D0 -> AL
  |
  v
OUT DX,AL (DX=0740H) -> IOWR=0, A1A0=00 -> AL latched in Port A -> LEDs glow
  |
  v
BL=0 (counter), CH=8 (loop count)
  |
  v
+--> ROL AL : MSB goes into Carry
|      Carry = 1 ? --yes--> INC BL (switch ON counted)
|      Carry = 0 ? --no---> skip
|    DEC CH ; CH != 0 ? -- yes --+
+----------------------------------+
  | (CH = 0, all 8 switches checked)
  v
AL = BL ; DX = 0744H -> OUT -> count appears on Port C lower (PC3-PC0)
  |
  v
HLT
```

**In words:**
1. Processor first *programs* the 8255 by writing 82H to the control register (address 0746H).
2. It *reads* Port B: each switch is a bit (closed to +5 V = 1, closed to ground = 0).
3. The same byte is *written* to Port A, so each LED shows its switch state (LED on = switch on).
4. The byte is rotated bit by bit; every 1 increments BL, so BL = number of ON switches.
5. BL is written to Port C, so PC3–PC0 show the count in binary (maximum 8 = 1000B).
6. Address lines: 8086 A2, A1 reach the 8255's A1, A0, so the port addresses step by 2 (0740H, 0742H, 0744H, 0746H). That is why `SUB DX,04` goes from CWR to Port B and `SUB DX,02` from Port B to Port A.

**Example:** switches = 1011 0101B (B5H) → LEDs show 10110101 → five switches ON → Port C lower = 0101B.

## 8. Example 2 – 4×4 Keyboard Interface (Slides 12–15, Problem 5.11)

**Problem:** Interface a 4×4 keyboard with 8086 via 8255; write ALP to detect a key closure and return key code in AL. Debounce period = 10 ms; **DEBOUNCE** is a given 10 ms delay routine. Use software debouncing.

### Principle (Slide 12)

- **Port A = output** → selects (grounds) one **row** at a time.
- **Port B = input** → senses the **column** lines (a closed key pulls its column low).
- Keyboard lines are polled until a key closure is sensed, then DEBOUNCE is called.
- Key code is decided from the **grounded row** and the **low column**.

### Circuit (Slide 13, Fig. 5.21)

- Port A lines PA3–PA0 drive the 4 rows. A 10 kΩ pull-up resistor is on each line.
- Port B lines PB3–PB0 read the 4 columns, each pulled up to +5 V through **10 kΩ**.
- A key at (row, column) connects that row to that column.
- 8255 A1, A0 ← 8086 A2, A1. CS̅ comes from a gate decoding A15–A12 and A0. RD̅/WR̅ ← IORD̅/IOWR̅.
- Port addresses: Port A = **8000H**, Port B = **8002H**, CWR = **8006H** (as used in the program).

### Control word

`82H` – Port A output, Port B input, Mode 0.

### Algorithm / Program (Slides 14–15)

1. Initialise 8255 with CWR = 82H (DX = 8006H); BL = 00H (key code).
2. **WAIT loop:** ground **all rows** (output 00H on Port A), read Port B, mask lower nibble (`AND AL, 0FH`), compare with 0FH. If equal → no key pressed → loop (`JZ WAIT`).
3. Key found → `CALL DEBOUNCE` (wait 10 ms).
4. Load `AL = 7FH` (rotated pattern to ground one row at a time), `BH = 04H` (row counter).
5. **NXTROW:** `ROL AL,01` → next row ground pattern; save in CH; output on Port A; read Port B; mask with 0FH; `CL = 04H` (column counter).
6. **NXTCOL:** `ROR AL,01` moves D0 into carry. If **CF = 0** → key found (`JNC CODEKY`); else `INC BL`, `DEC CL`, `JNZ NXTCOL`.
7. If no key in this row: restore AL from CH, `DEC BH`, `JNZ NXTROW`; if all rows done → `JMP WAIT`.
8. **CODEKY:** `MOV AL, BL` → key code (0–15) in AL.

**Key code = (row number × 4) + column number**, built by BL incrementing per column checked.

### How the system works – step-by-step flow (4×4 keyboard)

```
Start -> CWR = 82H (Port A out, Port B in)
  |
  v
Ground ALL rows (Port A = 00H)
  |
  v
WAIT: read Port B, mask low nibble
  all columns = 1111 ?  -- yes (no key) --> back to WAIT
  | no (some column pulled low = a key is pressed)
  v
CALL DEBOUNCE (10 ms) -> contact bounce dies out
  |
  v
AL = 7FH (pattern that grounds ONE row), BH = 4 rows
  |
  v
NXTROW: rotate pattern -> output on Port A (only one row grounded)
  read Port B (columns), CL = 4
  |
  v
NXTCOL: rotate columns into carry
   CF = 0 ? --yes--> CODEKY: AL = BL = key code -> DONE
   CF = 1 ? --no---> BL++ , CL-- ; CL != 0 -> next column
  |
  v (all 4 columns high: key not in this row)
BH-- ; BH != 0 -> NXTROW (ground next row)
  |
  v (all rows done: it was a bounce/false key)
JMP WAIT
```

**In words:**
1. **Keyboard hardware:** keys sit at row/column crossings. Rows are driven by Port A (output). Columns are read by Port B (input) and held high by 10 kΩ pull-ups. A pressed key connects its row to its column.
2. **Detect any key:** all rows are grounded at once. If any key is pressed, its column is pulled low, so Port B ≠ 0FH. Until then the program loops in WAIT.
3. **Debounce:** mechanical contacts chatter for a few ms. The 10 ms delay lets the contact settle before it is trusted.
4. **Locate the key:** only one row is grounded at a time. For each row, the columns are read. The row that gives a low column holds the pressed key. The column is found by shifting bits through the carry.
5. **Key code:** BL starts at 0 and increments for every column passed without a key, across all rows. So the code is row × 4 + column (0 to 15) and is returned in AL.
6. If no key is found after all rows, the press was a false trigger and the program returns to WAIT.

**Example:** key in row 1 (second row), column 2 → BL counts 4 (row 0) + 2 = key code 6.

## 9. Example 3 – Multiplexed 7-Segment Display (Slides 16–19, Problem 5.13)

**Problem:** Interface 8255 with 8086 with **80H as Port A address**. Interface **five 7-segment displays**. Write instructions to continuously display **1, 2, 3, 4, 5** in positions starting with 1 at the least significant position.

### Principle (Slide 16)

- **Port A** carries segment data (multiplexed to all displays).
- **Port B** selects (grounds) **one display at a time**.
- Displays are **common cathode**: logic **1** on a segment line **glows** it, **0 blanks** it.
- Display is selected by logic **1** on a Port B line which drives a **transistor** that grounds the common cathode.
- **Multiplexing + persistence of vision** makes all 5 digits appear lit.

### Circuit (Slide 17, Fig. 5.26)

- **PA7–PA0** → **74LS244 buffer** → segment lines dp, a, b, c, d, e, f, g of all displays (in parallel).
- **PB0–PB4** → each through **10 kΩ** to base of an NPN transistor; transistor emitter to ground, collector to the common cathode of one display (via a resistor).
- CS̅ from a gate decoding **A7–A3 and A0**. A1, A2 of 8086 → A0, A1 of 8255.
- Port addresses: Port A = **80H**, Port B = **82H**, CWR = **86H**.
- Note: the diagram shows a 74LS244 buffer to provide the segment current drive.

### Segment code table (Slide 18, Table 5.11)

PA7 = dp, PA6 = a, PA5 = b, PA4 = c, PA3 = d, PA2 = e, PA1 = f, PA0 = g.

| Digit | dp a b c d e f g | Code |
|---|---|---|
| 1 | 1 1 0 0 1 1 1 1 | **CFH** |
| 2 | 1 0 0 1 0 0 1 0 | **92H** |
| 3 | 1 0 0 0 0 1 1 0 | **86H** |
| 4 | 1 1 0 0 1 1 0 0 | **CCH** |
| 5 | 1 0 1 0 0 1 0 0 | **A4H** |

> These codes treat a **0 as segment ON** (so 1 = "CFH" lights only b and c). That conflicts with the slide text (1 = glow) but matches the table. Check with your instructor which convention your exam expects.

### Program (Slide 19)

```asm
AGAIN: MOV CL, 05H        ; number of displays
       MOV BX, 2000H
       MOV DS, BX         ; DS for look-up table
       MOV CH, 01H        ; first number to display
       MOV AL, 80H
       OUT 86H, AL        ; CWR = 80H (all ports output, Mode 0)
       MOV DL, 01H        ; enable LSB display
NXTDGT: MOV BX, 0000H     ; pointer to look-up table
       MOV AL, CH
       XLAT               ; AL = code from table
       OUT 80H, AL        ; segment data on Port A
       MOV AL, DL
       OUT 81H, AL        ; enable display (Port B)
       ROL DL             ; next display
       INC CH             ; next number
       DEC CL
       JNZ NXTDGT         ; next digit
       JMP AGAIN          ; repeat forever
```

**Control word 80H** = I/O mode, Mode 0, **all ports output**.

### How the system works – step-by-step flow (multiplexed 7-segment)

```
Start (AGAIN): CL = 5 (digits), CH = 1 (first number), DS -> look-up table
  |
  v
CWR (86H) = 80H : Port A and Port B both output
  |
  v
DL = 01H  (selects display 1, the least significant)
  |
  v
NXTDGT: AL = CH ; XLAT -> AL = 7-segment code of that number
  |
  v
OUT 80H,AL : segment code on Port A -> 74LS244 -> segment lines of ALL displays
  |
  v
AL = DL ; OUT 81H,AL : Port B line = 1 -> transistor ON
   -> common cathode of ONE display grounded -> only that digit glows
  |
  v
ROL DL (next display) ; INC CH (next number) ; DEC CL
  CL != 0 ? -- yes --> NXTDGT
  | no (all 5 shown)
  v
JMP AGAIN  (repeat forever)
```

**In words:**
1. **Why multiplex:** five displays would need 5 × 8 = 40 lines. By sharing the 8 segment lines (Port A) among all displays and selecting one digit at a time (Port B), only 8 + 5 = 13 lines are needed.
2. **Segment data:** the code for the digit (from the look-up table via XLAT) is output on Port A. It reaches every display, but only the selected one can light.
3. **Digit select:** a 1 on a Port B line turns on that line's transistor, grounding the common cathode of that one display. The others stay off.
4. **Scanning:** DL is rotated left, so the select pattern moves 01H → 02H → 04H → 08H → 10H. CH increments, so the digits are 1, 2, 3, 4, 5, with 1 on the least significant display.
5. **Persistence of vision:** the loop repeats endlessly and fast, and each digit is refreshed many times a second. The eye sees all five digits lit together as **12345**.
6. **74LS244 buffer:** the 8255 port lines cannot supply enough current for the segments, so the buffer drives them. The transistors similarly carry the combined segment current of a digit.

**Timeline of one scan:** display 1 shows "1" → display 2 shows "2" → display 3 shows "3" → display 4 shows "4" → display 5 shows "5" → repeat.

## 10. Important Points to Remember

1. 8255 = 40-pin, 24 I/O lines, 3 ports, 2 groups (A, B).
2. CS̅, RD̅, WR̅ are **active low**.
3. A1 A0: 00 = A, 01 = B, 10 = C, 11 = CWR.
4. CWR bit 7: **1 = I/O mode, 0 = BSR mode**.
5. In CWR, **1 = input, 0 = output** for ports.
6. BSR affects **only Port C bits**.
7. **RESET** makes all ports **input**.
8. Port A can work in Modes 0, 1, 2; Port B in Modes 0, 1 only.
9. Interfacing with 8086: connect 8255 to **lower data bus (D0–D7)**; 8086 A1, A2 → 8255 A0, A1 so port addresses are **even** and 2 apart.
10. Control word values to know: **82H** (A out, B in, C out), **80H** (all out), **BSR set/reset = 0xxx xxx1 / 0xxx xxx0**.
11. Software debouncing = wait ~10 ms after key detection, then re-read.
12. Multiplexed display: segment data common, digit-select line changes; refresh fast enough for persistence of vision.
